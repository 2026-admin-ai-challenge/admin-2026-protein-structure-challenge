# 운영진 가이드

관리자 화면은 관리자 계정으로 로그인한 뒤 `/admin` 또는 Admin 탭에서 엽니다. 여섯 개 메뉴가 있습니다.

| 메뉴 | 하는 일 |
| --- | --- |
| 현황·설정 | 대기열·실패 건수, 채점 작업자 상태, 일정·횟수·정책 설정, 대회 열기/닫기, 순위 동결, 최종 공개, 대회 초기화 |
| 팀·계정 | 팀 생성·이름 변경·삭제, 계정 발급, 비밀번호 재설정, 차단 |
| 제출·대기열 | 전체 제출 조회, 상태·실패 사유 필터, 실행 로그, 다시 채점, 횟수 복구, ZIP 받기·삭제, 파일 정합성 검사 |
| 특별상 | 성능 대비 파일 용량, 첫 제출 이후 순위 상승 두 특별상의 계산표와 수상팀 기록 |
| 데이터 | 데이터 버전·파일·SHA-256 확인, 공개 승인, 변경 검사, 잠금 |
| 조작 기록 | 누가 언제 무엇을 했는지 |

## 대회 전

대회 시작 전까지는 **관리자 계정으로 로그인한 사람에게만** 본 사이트가 보입니다. 그 밖의 사람은 `/`, `/admin` 등 어느 주소로 들어와도 D-day 카운트다운과 참가 신청 버튼만 보고, 대회 주제는 페이지 소스에도 드러나지 않습니다. 운영진은 카운트다운 오른쪽 위 "운영진 로그인"으로 로그인하면 본 사이트로 들어가 준비할 수 있습니다. 시작 시각(기본 2026-11-01 13:00 KST)이 지나면 모두에게 저절로 본 사이트가 열립니다. 시각을 바꾸거나 미리 열려면 `.env`에 `LAUNCH_AT`(예: `2026-11-01T13:00:00+09:00`, 지난 시각이면 즉시 공개)을, 신청 폼을 바꾸려면 `APPLY_URL`을 넣고 `docker compose up -d web api`를 실행합니다. API도 같은 `LAUNCH_AT`으로 공개 전 베이스라인 다운로드를 막으므로 web만 다시 띄우면 두 시각이 어긋납니다.

1. **관리자 계정**: `docker compose exec api python -m app.create_admin`. 같은 명령으로 관리자 비밀번호도 재설정합니다.
2. **참가자 계정**: `accounts/participants.csv`를 확인·수정한 뒤 불러옵니다.
   ```bash
   docker compose exec -T api python -m app.sync_accounts < accounts/participants.csv
   # Windows PowerShell은 < 를 지원하지 않으므로 아래처럼 실행
   cmd /c "docker compose exec -T api python -m app.sync_accounts < accounts\participants.csv"
   ```
   팀 이름을 실제 팀명으로 바꾸려면 시트의 `team_name`을 고치고 다시 실행합니다. 그 팀의 제출 기록은 그대로 따라갑니다.
3. **데이터 승인**: "데이터" 메뉴에서 연결된 버전과 검증 결과를 확인하고 "현재 버전 승인"을 누릅니다. 승인해야 대회 기간에 학습 데이터 다운로드가 열립니다. 확정했다면 "버전 잠금"을 겁니다.
4. **일정과 정책**: "현황·설정"에서 시작·종료 시각, 팀당 제출 횟수, 실패 제출 차감, 최종 순위 제출물을 저장합니다. 확정된 차감 기준을 적용하려면 **실패 제출 차감(`count_failed`)을 켜 둡니다.** ZIP 규격 위반·서버 오류만 미차감이며, 예측 출력 형식 오류를 포함한 나머지 채점 실패는 1회 차감합니다. 이 설정을 끄면 모든 실패가 미차감되므로 대회 운영 중에는 끄지 않습니다.
5. **채점 작업자 확인**: 작업자가 "정상"이어야 합니다. "mock" 표시가 보이면 점수가 가짜이므로 실제 대회용 설정이 아닙니다.
6. **리허설**: 베이스라인 ZIP을 실제로 올려 접수 ID → 대기 → 채점 → Public 순위까지 확인합니다. 큰 ZIP 업로드, 서버 재시작, 백업 복구도 한 번씩 해 봅니다.
7. **대회 열기**: "Open competition".

## 계정 전달과 문의 대응

- 참가자는 **팀 이름을 아이디로**, 배부된 비밀번호로 로그인합니다. 팀 이름은 대소문자·띄어쓰기를 구분하지 않으므로 대소문자만 다른 팀 이름은 만들 수 없습니다. 계정 시트의 `username`은 계정을 구분하는 내부 ID이며 로그인에는 쓰지 않습니다. 운영진은 운영진 팀 이름이나 관리자 아이디로 로그인합니다. 관리자 아이디 로그인에는 시도 제한이 없습니다.
- 팀 이름을 바꾸면 그 팀의 로그인 이름도 바로 바뀝니다. 팀에 알려 주세요.
- 계정 시트에는 비밀번호 원문이 있습니다. Git에 올리지 말고 팀별로 따로 전달합니다.
- 화면에서 발급·재설정한 임시 비밀번호는 **그때 한 번만** 표시됩니다. 닫기 전에 전달하세요. 다시 볼 방법은 없고 재설정만 가능합니다.
- 비밀번호를 재설정하면 그 계정의 기존 로그인은 즉시 풀립니다.
- 화면에서 바꾼 비밀번호는 계정 시트에 반영되지 않습니다. 이후 시트를 다시 불러오면 시트의 비밀번호로 돌아가므로, 한 가지 방법만 쓰거나 시트를 같이 고치세요.
- 차단하면 로그인과 제출이 막히고 그 계정의 제출이 순위에서 빠집니다.
- **팀 삭제**: 팀·계정에서 "팀 삭제"를 누르고 팀 이름을 입력합니다(대소문자·띄어쓰기 무시). 그 팀의 계정, 제출 기록, 보관 ZIP, 순위 항목이 **영구 삭제**되고 되돌릴 수 없습니다(조작 기록에는 남습니다). 테스트 팀이나 참가를 취소한 팀을 정리할 때 씁니다. 대회 중 기록을 남겨야 하면 삭제 대신 차단하세요. 채점 중인 제출이 있으면 끝난 뒤 다시 시도하고, 최종 순위 공개 후에는 삭제할 수 없습니다. 계정 시트에 그 팀이 남아 있으면 다음 `sync_accounts` 때 다시 만들어지므로 시트에서도 지웁니다.

## 대회 중

- **대기열**: "현황·설정"의 대기 중·채점 중 건수와 가장 오래된 접수 시각을 봅니다. 화면은 탭이 보이는 동안 10초마다 갱신됩니다.
- **작업자가 응답 없음**: `docker compose ps`, `docker compose logs --tail 100 worker`를 확인하고 `docker compose restart worker`로 다시 띄웁니다. 대기 중이던 제출은 그대로 남아 이어서 채점됩니다.
- **실패 문의**: "제출·대기열"에서 접수 ID로 검색하고 "로그"로 실행 출력을 확인합니다. 로그에는 평가 입력이 섞여 있을 수 있으니 **참가자에게 그대로 전달하지 마세요.**
- **서버 탓으로 실패한 제출**: `system_error`(와 ZIP 규격 위반 `zip_invalid`)는 자동으로 횟수를 차감하지 않습니다. 원인을 고친 뒤 "다시 채점"을 누릅니다. 다시 채점하면 그 제출은 다시 1회 차감 대상이 되고(결과가 또 서버 오류면 미차감), 팀 한도는 확인하지 않습니다. 한도를 넘게 되면 "횟수 복구"로 조정합니다.
- **횟수 복구**: 운영진 판단으로 한 건의 횟수를 돌려줄 때 "횟수 복구"를 누릅니다. 기록이 남고, 그 제출을 다시 채점해도 복구한 횟수는 유지됩니다.
- **순위 동결**: 종료 전 순위를 가리려면 "Freeze leaderboard". 제출과 채점은 계속됩니다.

## 제출 파일 관리

기본 보관 정책은 `ZIP_RETENTION=best_public`입니다. 채점이 끝나면 팀별 최고 Public 점수 ZIP을 남기고 낮은 점수·동점·일반 실패 ZIP은 자동 정리합니다. 더 높은 점수가 나오면 이전 최고 ZIP을 교체합니다. 동점 선택은 리더보드와 동일하게 ZIP이 더 작은 제출, 크기도 같으면 먼저 접수한 제출입니다. 같은 점수라도 더 작은 ZIP이 들어오면 보관 ZIP이 그것으로 바뀝니다.

제출 기록, Public/Private 점수, 예측, 실행 로그, 해시와 횟수는 남습니다. 파일 정리는 `file.retention` 조작 기록과 삭제 사유로 확인할 수 있습니다. 정리된 ZIP은 다운로드하거나 다시 채점할 수 없으며, 필요하면 참가자가 새 ZIP을 제출해야 합니다.

대기·실행 중 제출과 재시도가 필요한 `system_error` ZIP은 보호합니다. 동결·최종 리더보드가 참조하는 ZIP도 보존합니다. `final_selection=best_private`이면 팀의 Private 최고 ZIP도 보존하므로 Public 최고 ZIP과 다르면 두 개를 유지합니다. 최종 선택 규칙은 `best_public`으로 확정됐으니 이 설정을 바꾸지 마세요. 바꿔도 이미 정리된 과거 ZIP은 복원되지 않습니다.

채점 작업자는 시작 후 기존 완료 제출에도 같은 정책을 적용합니다. DB에 점수와 파일 정리 기록을 커밋한 다음 ZIP을 삭제하고, 일시적인 디스크 오류로 삭제하지 못한 파일은 다음 작업자 실행에서 재시도합니다. 작업자가 제출 볼륨에 쓰기 권한을 가져야 합니다. 모든 ZIP을 계속 보관하려면 API·worker에 `ZIP_RETENTION=keep_all`을 동일하게 설정합니다.

- **팀별 용량**: "팀·계정"의 제출 횟수 칸에 보관 중인 ZIP 개수와 용량이 나옵니다.
- **ZIP 받기**: "제출·대기열"에서 해당 제출의 "ZIP 받기"를 누릅니다. 재현 심사용이며 받은 사실이 조작 기록에 남습니다. 파일 이름은 `team팀번호-submission접수ID-원래이름.zip`입니다.
- **파일 삭제**: "파일 삭제"를 누르고 사유를 적습니다. 파일만 지워지고 점수·기록·제출 횟수는 그대로입니다. **되돌릴 수 없고**, 그 제출은 다시 채점할 수 없게 됩니다. 순위에 반영된 제출("순위 반영" 표시)과 채점 중인 제출은 삭제 버튼이 막혀 있습니다.
- **정합성 검사**: "파일 정합성 검사"는 DB 기록과 디스크를 비교해 없어진 파일, 크기가 달라진 파일, 기록 없는 파일을 알려 줍니다. 아무것도 바꾸지 않습니다. 내용 해시까지 확인하려면 서버에서 `docker compose exec api python -m app.check_files --hash`를 실행합니다.
- `ZIP_RETENTION=keep_all`이면 자동 삭제가 없습니다. 이때 디스크가 부족하면 실패한 제출과 순위에 반영되지 않은 제출의 파일부터 정리하세요. 수상 후보의 제출물은 재현 심사가 끝날 때까지 지우지 않습니다.

## 종료

1. 종료 시각이 지나면 새 제출은 받지 않습니다. 그 전에 접수된 제출은 계속 채점됩니다.
2. "Close competition"으로 대회를 닫습니다.
3. 대기 중·채점 중이 0이 될 때까지 기다립니다. 남아 있으면 최종 공개가 거부됩니다.
4. "제출·대기열"에서 실패 제출과 차단 계정, Public·Private 점수를 검토합니다.
5. "Publish final leaderboard". **되돌릴 수 없습니다.** 이후 대회 재개, 계정 상태 변경, 다시 채점이 막힙니다. 같은 사이트로 다시 하려면 아래의 초기화를 씁니다.
6. "특별상"에서 계산 기준을 최종 순위로 두고 두 특별상의 수상팀을 기록합니다(아래 [특별상](#특별상)).
7. DB와 제출 ZIP을 백업합니다([배포 문서](deployment.md) 참고). 수상 후보의 제출물과 기록은 재현 심사가 끝날 때까지 보관합니다.

## 특별상

"특별상" 메뉴는 두 특별상의 계산표를 보여 주고, 운영진이 고른 팀을 수상팀으로 기록합니다. 계산 기준은 Public 순위나, 최종 공개 뒤에는 최종 순위(Private)입니다. 두 상 모두 각 팀이 그 순위표에 올린 제출물(ZIP 보관과 최종 순위에 쓰는 바로 그 제출물)로 계산합니다. 운영진(ADMIN 계정)의 시험용 모델과 차단된 계정은 계산표에 들어가지 않으며, 표의 순위도 참가 팀끼리의 순위입니다.

- **성능 대비 파일 용량**: 순위표에 오른 팀들의 점수와 ZIP 용량을 각각 min-max로 0.01~1에 맞춘 뒤, `점수' ÷ 용량'`이 큰 팀이 1위입니다. 하한 0.01은 가장 작은 ZIP의 용량'이 0이 되어 무한대가 되는 것을 막습니다. 모든 팀의 값이 같으면 모두 1로 둡니다. ZIP 기록이 없는 제출(파일 관리 도입 전 제출)은 빠집니다. 같은 값이면 순위가 높은 팀이 앞입니다.
- **첫 제출 이후 순위 상승**: 팀의 첫 점수가 나온 순간(채점 완료 시각) 같은 순위표에서의 순위, 즉 그때까지 점수가 있던 팀들 사이의 순위에서 지금 순위를 뺀 값이 큰 팀이 1위입니다. 처음 제출한 팀은 그때 1위(1팀 중)이므로 오를 수 없고, 늦게 처음 제출한 팀일수록 그때 순위가 낮게 잡힙니다. 순위가 오르지 않은 팀은 기록할 수 없습니다. 같은 값이면 지금 순위가 높은 팀이 앞입니다.
- "수상 기록"을 누르면 그 팀의 계산표 한 줄(순위, 점수, 용량, 그때 순위 등)이 기록 당시 값으로 저장됩니다. 이후 순위나 팀 이름이 바뀌어도 기록은 그대로이며, 다시 기록하면 그 상의 수상팀만 바뀝니다. 기록과 삭제는 조작 기록(`award.record`, `award.delete`)에 남습니다.
- 대회 초기화는 특별상 기록도 지웁니다.

## 다음 대회 준비 (초기화)

리허설을 마쳤거나 대회가 끝난 뒤, 같은 사이트로 새 대회를 열 때 씁니다.

1. 대회를 닫습니다("Close competition"). 채점 중인 제출이 있으면 초기화가 거부되니 끝날 때까지 기다립니다. 120초 넘게 신호가 없는 채점 중 제출은 막지 않습니다(`WORKER_STALE_SECONDS`).
2. **초기화는 되돌릴 수 없고 따로 보관하지도 않습니다.** 제출 ZIP, 점수, 순위, 특별상 기록, 조작 기록이 영구 삭제되므로 남겨야 하면 [배포 문서](deployment.md#백업과-복구)의 명령으로 DB와 제출 ZIP을 먼저 백업합니다.
3. "현황·설정" 맨 아래 "Reset competition"을 누르고 `초기화`를 입력합니다.

| 비워지는 것 | 그대로인 것 |
| --- | --- |
| 모든 제출(대기 중 포함)과 파일 기록, Public·최종 순위, 특별상 기록 | 팀, 계정, 비밀번호, 차단 상태 |
| 디스크의 제출 ZIP 전부(기록 없는 ZIP 포함), 1시간 넘게 멈춘 업로드 조각 | 팀당 제출 횟수, 실패 차감, 최종 순위 제출물 설정 |
| 조작 기록, 채점 작업자 목록, 요청 제한 카운터 | 데이터 승인·잠금 |
| 접수 번호(1번부터 다시 시작), 시작·종료 시각, 순위 동결, 최종 공개 상태 (대회는 닫힌 상태) | 대회 이름 |

- 팀마다 제출 횟수가 다시 처음부터 셉니다.
- 채점 작업자 목록은 실행 중인 worker가 몇 초 안에 다시 보고하면서 채워집니다.
- 차단 상태는 풀리지 않습니다. 이전 대회의 차단을 새 대회에 이어 가지 않으려면 "팀·계정"에서 해제합니다.
- 참가자가 바뀌면 새 계정 시트를 `sync_accounts --exclusive`로 불러와 시트에 없는 계정을 막습니다.
- 데이터를 바꾸려면 "데이터" 메뉴에서 잠금을 풀고 새 버전을 승인합니다.
- 새 일정을 저장해야 대회를 열 수 있습니다.
- 새 조작 기록은 `competition.reset` 한 줄(지운 건수와 이전 일정·상태)로 시작합니다. 디스크에서 지우지 못한 ZIP이 있으면 실패 기록이 하나 더 남고, 그 ZIP은 "파일 정합성 검사"에 기록 없는 파일로 나옵니다.

## 장애 점검표

| 증상 | 확인 | 조치 |
| --- | --- | --- |
| 사이트가 안 열림 | `docker compose ps` | `docker compose up -d`, `logs web api` |
| 로그인이 안 됨 | 팀 이름 철자(팀·계정의 현재 이름, 이름 변경 이력), 차단 여부, 조작 기록의 재설정 이력 | 바른 팀 이름 안내, 비밀번호 재설정 |
| 업로드가 중간에 끊김 | 프록시 본문 한도·시간 제한, 디스크 여유 | 한도 상향, `df -h` |
| 제출이 계속 대기 중 | 작업자 상태와 사유 | 이미지·정답·평가 입력 경로 확인, worker 재시작 |
| 전부 `system_error` | worker 로그 | 원인 해결 후 "다시 채점" |
| 전부 `runtime_error` | 한 건의 "로그" | 맨 윗줄 `installed from requirements.txt (…)`와 import 오류. `requirements.txt`에 빠진 패키지인지 확인 |
| 패키지 설치 `system_error` | 로그의 `package install failed`와 pip 출력 | PyPI 접속(방화벽·DNS), 설치 시간 초과면 `EVAL_INSTALL_TIMEOUT_SECONDS`. 해결 후 "다시 채점" |
| 설치가 매번 PyPI에서 받음 | 로그 맨 윗줄의 `(PyPI)` | 89개 목록 사본·이미지가 낡았는지 확인 후 이미지 재빌드 |
| 순위가 안 바뀜 | 동결 여부, mock/docker 평가기 일치 | 동결 해제, "Rebuild leaderboard" |

## 대회 전 리허설 기록

리허설 때 아래를 직접 실행하고 날짜와 결과를 남깁니다.

- [ ] 베이스라인 ZIP 접수부터 Public 순위 반영까지 걸린 시간
- [ ] 베이스라인·구조 기반 모델의 추론 시간과 최대 메모리 (이 컴퓨터, `EVAL_CPUS`·`EVAL_MEMORY` 값과 함께)
- [ ] 상한에 가까운 크기의 ZIP 업로드 성공
- [ ] 같은 팀 두 계정의 동시 제출이 합계 상한을 넘지 않음
- [ ] 채점 중 `docker compose restart worker` 후 제출이 다시 채점됨
- [ ] 서버 전체 재부팅 후 대기열 유지
- [ ] DB·제출 ZIP 백업과 복구
- [ ] 10분 초과 제출이 `timeout`으로 끝남
- [ ] 제출 코드에서 인터넷, 정답 파일, DB, Docker 소켓에 접근할 수 없음
